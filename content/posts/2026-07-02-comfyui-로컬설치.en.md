Claude is a text AI, so it can't draw on its own. But **if you attach an image-generation server running on your local PC**, a single "draw me a cat" is enough for Claude to refine the prompt and produce the image. Today I'm writing up how I actually built this by installing ComfyUI + SDXL on a gaming laptop (RTX 4060). Cost: zero, and it works without an internet connection.

## Which tool should do the drawing — three options

- **Automatic1111 WebUI (local)** — A traditional web UI, so it's the easiest to poke at directly, but its memory management is loose, which makes SDXL a stretch on 8GB of VRAM.
- **Nano Banana (cloud, Gemini API)** — No installation needed, just an API key, and the quality is good, but it costs about 50 KRW per image, requires internet, and stamps a watermark.
- **ComfyUI (local) ← final choice** — The node UI is unfamiliar, but since Claude calls it via the API anyway, that doesn't matter. Of the three candidates it has **the best VRAM efficiency** (decisive on an 8GB laptop), the entire workflow is JSON so it's **the cleanest for a program to call**, and it's free, unlimited, and offline.

## The overall architecture

The core idea is simple. Claude only "conducts"; the local GPU does the drawing.

```
User: "Draw the Seoul night skyline at sunset"
   ↓
Claude: Korean request → convert & enrich into an English prompt
   ↓
ComfyUI server (local, http://127.0.0.1:8188)
   ↓
The SDXL model generates the image on the RTX 4060 (20–40 sec)
   ↓
Claude displays the finished PNG in the chat
```

- **ComfyUI**: An open-source program that runs Stable Diffusion. It provides a REST API so an external program (Claude) can call it.
- **SDXL**: Stability AI's image-generation model. 1024×1024 native resolution.

## Can my PC handle it? — Checking the specs

The minimum requirements I checked before installing, and my laptop's (HP Victus 16) specs:

| Item | Required spec | My laptop | Verdict |
|---|---|---|---|
| GPU VRAM | 8GB or more recommended (SDXL) | RTX 4060 Laptop 8GB | Pass |
| RAM | 16GB | 16GB | Pass |
| Disk | About 20GB | 351GB free | Pass |

8GB of VRAM is effectively the bottom line for SDXL. At 6GB or less, you're better off with the lighter SD 1.5 model.

## Installation (on Windows 11)

### 1. Clone ComfyUI + virtual environment

```powershell
git clone --depth 1 https://github.com/comfyanonymous/ComfyUI C:\ComfyUI
python -m venv C:\ComfyUI\venv
```

### 2. Install PyTorch (CUDA build)

A plain `pip install torch` installs the CPU build, so you **must specify the CUDA index** to use the GPU.

```powershell
C:\ComfyUI\venv\Scripts\python.exe -m pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu128
```

After installing, confirm the GPU is detected:

```powershell
C:\ComfyUI\venv\Scripts\python.exe -c "import torch; print(torch.cuda.is_available())"
# Should print True
```

### 3. Dependencies + downloading the SDXL model

```powershell
C:\ComfyUI\venv\Scripts\python.exe -m pip install -r C:\ComfyUI\requirements.txt

# SDXL base model (~6.5GB) → save to models\checkpoints\
curl.exe -L -o C:\ComfyUI\models\checkpoints\sd_xl_base_1.0.safetensors https://huggingface.co/stabilityai/stable-diffusion-xl-base-1.0/resolve/main/sd_xl_base_1.0.safetensors
```

### 4. Run the server

```powershell
C:\ComfyUI\venv\Scripts\python.exe C:\ComfyUI\main.py --port 8188
```

Opening `http://127.0.0.1:8188` in a browser brings up the node-based UI, but if your goal is Claude integration you'll rarely touch the UI directly.

## Connecting to Claude

Two endpoints are the heart of ComfyUI's API.

- `POST /prompt` — Submit a workflow (JSON) and it returns a `prompt_id`
- `GET /history/{prompt_id}` — Once generation finishes, it comes back with the result image's filename

I wrote a single Python script (`generate.py`) that calls these, and registered one **skill** in Claude Code. A skill is an instruction sheet saying "when a request like this comes in, run this script":

```markdown
---
name: draw-local
description: When the user requests a drawing, generate it with local ComfyUI. Translate Korean prompts into English.
---
C:\ComfyUI\venv\Scripts\python.exe C:\ComfyUI\generate.py "PROMPT"
After running, when SAVED <path> is printed, display that PNG in the chat.
```

Now when you tell Claude "draw ~," it handles everything on its own: ① auto-start the server if it's off → ② translate and enrich the Korean into an English prompt → ③ generate → ④ display the image in the chat.

These are images actually generated on this laptop. How you write the prompt is half the quality.


### Example 2 — Landscape + mood keywords

```

```

![Mountain lake at dawn](/images/comfyui/mountain-lake.jpg)

### Example 3 — Real location + time of day + style

```
Seoul city skyline at sunset, Namsan Tower and Han River, glowing orange and purple sky,
city lights turning on at dusk, skyscrapers, photorealistic, cinematic lighting, high detail
```

![Seoul night skyline at sunset](/images/comfyui/seoul-sunset.jpg)

**Prompt tips**: ① Write in English (SDXL's training skews overwhelmingly toward English). ② Tack style keywords like `photorealistic` and `cinematic lighting` onto the end. ③ Split off anything you want to avoid into a negative prompt (`blurry, low quality, watermark...`).

## Measured performance (RTX 4060 Laptop, 8GB)

- First generation: about 1 minute (including server startup + loading the model into VRAM)
- After that: **20–40 sec per image** (1024×1024, 28 steps)
- Dropping to 20 steps takes ~24 sec, with little difference in quality

## Wrapping up

- With an 8GB VRAM laptop, local SDXL generation is plenty practical.
- The heart of the Claude integration is just two things: "a script that calls the ComfyUI API + registering a skill."
- Advantages over a cloud API (Nano Banana, etc.): free, unlimited, offline. Downsides: cloud models still win on quality and text rendering.
- Next step: I'm also considering adding Nano Banana (the Gemini image API) so I can pick between local and cloud.
