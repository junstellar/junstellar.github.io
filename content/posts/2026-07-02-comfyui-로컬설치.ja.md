Claude（クロード）はテキスト AI なので、自分で絵を描くことはできない。だが、**ローカル PC で動く画像生成サーバーをつないでやれば**、「猫を描いて」の一言でクロードがプロンプトを整えて絵を作らせられる。今日は、ゲーミングノート PC（RTX 4060）に ComfyUI + SDXL を入れて、これを実際に構築した過程をまとめる。費用は 0 円、インターネットなしでも動く。

## どのツールで描かせるか — 選択肢 3 つ

- **Automatic1111 WebUI（ローカル）** — 昔ながらの Web UI で、自分で触るには一番簡単だが、メモリ管理が緩く、VRAM 8GB では SDXL が重い。
- **Nano Banana（クラウド、Gemini API）** — インストール不要で API キーさえあればよく、品質も良いが、1 枚あたり約 50 ウォン + インターネット必須 + ウォーターマークが入る。
- **ComfyUI（ローカル）← 最終選択** — ノード UI は不慣れだが、どのみちクロードが API で呼ぶので関係ない。3 候補の中で **VRAM 効率が最も良く**（8GB ノートには決定的）、ワークフロー全体が JSON なので **プログラムから呼ぶのが一番きれい**で、無料・無制限・オフラインだ。

## 全体の構造

核となるアイデアはシンプルだ。クロードは「指揮」だけをして、絵はローカル GPU が描く。

```
ユーザー: 「夕焼けのソウルの夜景を描いて」
   ↓
クロード: 韓国語のリクエスト → 英語プロンプトに変換・補強
   ↓
ComfyUI サーバー（ローカル、http://127.0.0.1:8188）
   ↓
SDXL モデルが RTX 4060 で画像を生成（20〜40 秒）
   ↓
クロードが完成した PNG をチャットに表示
```

- **ComfyUI**: Stable Diffusion を動かすオープンソースのプログラム。REST API を提供し、外部プログラム（クロード）が呼び出せる。
- **SDXL**: Stability AI の画像生成モデル。1024×1024 のネイティブ解像度。

## 自分の PC で動くのか? — スペック確認

導入前に確認した最小条件と、自分のノート PC（HP Victus 16）のスペック:

| 項目 | 必要スペック | 自分のノート PC | 判定 |
|---|---|---|---|
| GPU VRAM | 8GB 以上推奨（SDXL） | RTX 4060 Laptop 8GB | 合格 |
| RAM | 16GB | 16GB | 合格 |
| ディスク | 約 20GB | 351GB の空き | 合格 |

VRAM 8GB が SDXL の事実上のギリギリのラインだ。6GB 以下なら、より軽い SD 1.5 モデルを使うほうがいい。

## 導入手順（Windows 11 の場合）

### 1. ComfyUI をクローン + 仮想環境

```powershell
git clone --depth 1 https://github.com/comfyanonymous/ComfyUI C:\ComfyUI
python -m venv C:\ComfyUI\venv
```

### 2. PyTorch（CUDA 版）のインストール

普通の `pip install torch` は CPU 版が入るので、GPU を使うには **必ず CUDA インデックスを指定**しなければならない。

```powershell
C:\ComfyUI\venv\Scripts\python.exe -m pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu128
```

インストール後、GPU 認識を確認:

```powershell
C:\ComfyUI\venv\Scripts\python.exe -c "import torch; print(torch.cuda.is_available())"
# True と出れば OK
```

### 3. 依存関係 + SDXL モデルのダウンロード

```powershell
C:\ComfyUI\venv\Scripts\python.exe -m pip install -r C:\ComfyUI\requirements.txt

# SDXL base モデル（~6.5GB） → models\checkpoints\ に保存
curl.exe -L -o C:\ComfyUI\models\checkpoints\sd_xl_base_1.0.safetensors https://huggingface.co/stabilityai/stable-diffusion-xl-base-1.0/resolve/main/sd_xl_base_1.0.safetensors
```

### 4. サーバー起動

```powershell
C:\ComfyUI\venv\Scripts\python.exe C:\ComfyUI\main.py --port 8188
```

ブラウザで `http://127.0.0.1:8188` を開くとノードベースの UI が出るが、クロード連携が目的なら UI を直接触ることはほとんどない。

## クロードと接続する

ComfyUI の API は 2 つのエンドポイントが核だ。

- `POST /prompt` — ワークフロー（JSON）を送ると `prompt_id` を返してくれる
- `GET /history/{prompt_id}` — 生成が終わると結果画像のファイル名が入って返ってくる

これを呼ぶ Python スクリプト（`generate.py`）を一つ作り、Claude Code（クロードコード）には **スキル（skill）** を一つ登録した。スキルとは「こういうリクエストが来たら、このスクリプトを実行しろ」という指示書だ:

```markdown
---
name: draw-local
description: ユーザーが絵をリクエストしたらローカルの ComfyUI で生成。韓国語プロンプトは英語に翻訳。
---
C:\ComfyUI\venv\Scripts\python.exe C:\ComfyUI\generate.py "PROMPT"
実行後、SAVED <パス> が出力されたら、その PNG をチャットに表示すること。
```

これでクロードに「〜描いて」と言えば、① サーバーが落ちていれば自動起動 → ② 韓国語を英語プロンプトに翻訳・補強 → ③ 生成 → ④ チャットに絵を表示、まで自分でやってくれる。

## 成果物 — プロンプト例 3 つ

実際にこのノート PC で生成した画像だ。プロンプトをどう書くかが品質の半分を決める。

### 例 1 — 人物/動物 + 照明の指定

```
a cute orange cat sitting on a windowsill, warm sunlight, photorealistic
```

![窓辺の猫](/images/comfyui/orange-cat.jpg)

### 例 2 — 風景 + 雰囲気のキーワード

```
a serene mountain lake at sunrise, mist over the water, photorealistic
```

![夜明けの山上湖](/images/comfyui/mountain-lake.jpg)

### 例 3 — 実在の場所 + 時間帯 + スタイル

```
Seoul city skyline at sunset, Namsan Tower and Han River, glowing orange and purple sky,
city lights turning on at dusk, skyscrapers, photorealistic, cinematic lighting, high detail
```

![夕焼けのソウルの夜景](/images/comfyui/seoul-sunset.jpg)

**プロンプトのコツ**: ① 英語で書くこと（SDXL は英語の学習比率が圧倒的）。② `photorealistic`、`cinematic lighting` のようなスタイルキーワードを後ろに付けること。③ 避けたい要素はネガティブプロンプト（`blurry, low quality, watermark...`）に分けること。

## 実測パフォーマンス（RTX 4060 Laptop, 8GB）

- 初回生成: 約 1 分（サーバー起動 + モデルの VRAM ロードを含む）
- 以降: **1 枚あたり 20〜40 秒**（1024×1024、28 ステップ）
- ステップを 20 に減らすと ~24 秒、品質の差は大きくない

## まとめ

- 8GB VRAM のノート PC なら、SDXL のローカル生成は十分実用的だ。
- クロード連携の核は「ComfyUI API を呼ぶスクリプト + スキルの登録」の 2 つだけ。
- クラウド API（Nano Banana など）に対する利点: 無料・無制限・オフライン。欠点: 品質とテキストレンダリングはクラウドモデルが優勢。
- 次のステップ: Nano Banana（Gemini 画像 API）連携を追加して、ローカル/クラウドを選んで使うことも検討中。
