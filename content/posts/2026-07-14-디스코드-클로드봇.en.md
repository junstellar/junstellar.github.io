## It started with Slack

I wanted a setup for managing team projects where you could summon Claude from a messenger by tagging it. Slack already has an official way to attach Claude (Claude in Slack, the "Claude Tag"), so that was my first stop — and it **required a Team plan.** For someone running solo or with a small group, upgrading an entire billing tier for one feature didn't add up.

So I flipped the approach: attach it to a messenger I already use. I narrowed down the candidates.

- **KakaoTalk** — out. There's simply no bot API for ordinary chat rooms. OpenBuilder is for 1:1 channel chatbots only, and unofficial automation risks getting your account suspended.
- **Telegram** — the official bot API is the simplest and has the lowest barrier to entry. But conversation is a single stream, so running several topics at once tangles fast.
- **Discord** — the final pick.

The reasons for Discord were clear.

- **Thread structure.** One mention creates one thread, so context separates by topic naturally. This lines up exactly with the `--resume` session mapping below.
- **Channel separation.** You can split channels by purpose — work, notes, schedule.
- **It handles attachments and code blocks properly.** Drop a file and go straight to "analyze this."
- **Fine-grained bot permissions.** What the bot can do and where is controlled at the server level.
- **Slash commands are first-class.** You can build something like `/add-schedule` with autocomplete and argument validation attached.
- It's free, and there are desktop and mobile clients, so it comes with me when I go out.

## The core architecture

```
Discord @mention → discord.py bot → claude -p (headless Claude Code) → send response
```

- `claude -p --output-format json` returns a `session_id` alongside the response. Map that to the Discord thread ID and store it, then attach `--resume <session_id>` to the next message and **each thread keeps its own conversation context.**
- If Claude Code is logged in with a subscription (Pro/Max), `claude -p` runs against that subscription quota, so **no Anthropic API billing is needed.** The cost problem that blocked me on the Slack side disappears here.
- Even in headless mode it **recognizes every MCP server and skill configured on that PC.** The environment I use on my own machine comes through to Discord as-is.

## An unexpected win: local note syncing solved itself

I'd been **keeping my notes as local files**, Obsidian-style. To read them on my phone, every service eventually nudges you toward a paid sync plan. Same wall as Slack.

But once I attached this bot, the problem vanished entirely. The note files stay local on my PC, and one mention in Discord is enough for Claude to read them and answer. **There's nothing to sync — because instead of moving the files, you send the question to where the files already are.**

Layering MCP on top makes it better. Hook up an internal system like Redmine over MCP and the bot pulls schedules and issues and **lays them out neatly right in the Discord chat.** Since it bundles local notes and MCP data into a single summary, "what's on today" is one chat line away without building a separate dashboard.

## What the bot does

- Mention → auto-creates a thread and answers there
- Auto-downloads attachments, then Claude analyzes them with the Read tool
- Slash commands (`/add-schedule`, `/list-schedule`, `/delete-schedule`) for deadline alerts (once the day before, then hourly on the day itself; delete = mark done)

## Security design

Since **every member of the server the bot sits in ends up using the Claude on my PC**, the tools have to be locked down. I restricted `--allowedTools` to the read/search family (Read, Glob, Grep, WebSearch, WebFetch) plus the MCP tools I want to permit (`mcp__redmine__list_issues` and so on), and blocked execution/write tools like Bash, Write, and Edit.

## Registering the Discord bot

In the developer portal:

1. New Application → issue a token from the Bot menu
2. **Turn on the MESSAGE CONTENT INTENT switch** — without it the bot can't read messages. The single most common mistake.
3. In the OAuth2 URL Generator, check the `bot` scope plus the permissions you need
4. Invite it to your server with the generated URL

So that other Claude subscribers can run it on their own token and their own subscription, I bundled it as a zip (bot code + `.env.example` + install guide + `setup.bat`). The setup.bat automates the Python (winget) and discord.py installs and generates the config file, leaving only the parts that need an account — issuing the Discord token, logging into Claude — to be done by hand.

## Where I got stuck, and how I got out

- **Python installed from the Store (MSIX) has a virtualized AppData**, so it can't read claude.exe at `%APPDATA%\Claude\claude-code\` (visible from PowerShell, but FileNotFoundError from Python). → Fixed by copying claude.exe to a folder outside AppData. It's a standalone executable, so copying is all it takes.
- **Putting Korean text in a batch file makes cmd mangle the command** (after `chcp 65001` the parser misreads byte offsets, producing phantom errors like `'laudeBot' is not recognized...`). → Keep .bat files ASCII-only.
- **Piping Korean through PowerShell breaks the encoding.** → Writing UTF-8 bytes straight to stdin from a Python subprocess is safe. Running Python also needs `-u` (unbuffered) plus `PYTHONUTF8=1` (without them, print gets trapped in the buffer so logs don't show, or it dies on emoji output).
- **If you launch the bot as a background process of an AI session, the bot dies when the session ends.** → It has to run in its own console, launched by double-clicking the .bat. Closing the console window kills the bot; minimizing is fine.
- Running two processes on the same bot token attaches both to the gateway, so **replies come out duplicated.**

## Notes and thoughts

- In the end I got past three separate "please upgrade your plan" prompts with one and the same move. Claude in Slack (Team plan), note syncing (subscription), API billing — **a single bot running on my own PC** cleared all three.
- The point wasn't where to host Claude; it was **cutting one doorway — a messenger — into the environment I'd already built on my PC** (MCP, skills, local files). That's why there was almost nothing new to configure.
