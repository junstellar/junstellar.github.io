## 始まりは Slack だった

チームのプロジェクト管理用に、「メッセンジャーでクロードをタグで呼んで使う」環境を作りたかった。Slack にクロードをつなぐ公式機能（Claude in Slack、いわゆるクロードタグ）がすでにあるのでそれを使うつもりだったが — **チームプランを要求された。** 一人、あるいは小規模で回している立場からすると、機能ひとつのために料金プランを丸ごと上げるのは納得がいかない。

そこで「なら自分が使っているメッセンジャーに直接つなごう」と方針を変え、候補を絞った。

- **カカオトーク** — 脱落。一般のチャットルームにつなげるボット API がそもそも存在しない。オープンビルダーは 1:1 チャンネルチャットボット専用で、非公式な自動化はアカウント停止のリスクがある。
- **Telegram** — 公式ボット API が最も簡単で、参入障壁も低い。ただし会話が一本の流れなので、複数のテーマを同時に回すとすぐ絡まる。
- **Discord** — 最終的にこれ。

Discord を選んだ理由ははっきりしていた。

- **スレッド構造。** メンション一つにスレッドが一つ生まれるので、テーマごとに文脈が自然に分かれる。これが後述の `--resume` セッション対応とぴったり噛み合う。
- **チャンネル分離。** 業務／メモ／予定のように用途別にチャンネルを分けられる。
- **添付ファイルとコードブロックをきちんと扱える。** ファイルを上げてそのまま「これ分析して」が通る。
- **ボット権限を細かく渡せる。** どのチャンネルで何ができるかをサーバー単位で制御できる。
- **スラッシュコマンドが一級市民。** `/予定登録` のようなものを補完・引数検証まで付けて作れる。
- 無料で、PC・モバイルの両クライアントがあるので外出先でもそのまま使える。

## 中核の構成

```
Discord @メンション → discord.py ボット → claude -p (headless Claude Code) → 応答を送信
```

- `claude -p --output-format json` は応答と一緒に `session_id` を返す。これを Discord のスレッド ID と対応づけて保存しておき、次のメッセージに `--resume <session_id>` を付ければ **スレッドごとに会話の文脈が保たれる。**
- Claude Code にサブスクリプション（Pro/Max）でログインしていれば `claude -p` はその契約枠で処理されるので、**Anthropic の API 課金は不要だ。** Slack 側で詰まった料金の問題がここで消える。
- headless モードでも、その PC に設定してある **MCP サーバーとスキルをすべてそのまま認識する。** 自分の PC で使っていた環境がそのまま Discord に出てくるわけだ。

## 予想外の収穫：ローカルメモの同期も一緒に解決した

Obsidian のように **メモをローカルファイルとして貯めていた** のだが、これをスマホでも見ようとすると、どのサービスも結局は有料の同期プランを勧めてくる。Slack のときとまったく同じ壁だ。

ところがこのボットをつないだら、その問題が丸ごと消えた。メモファイルは自分の PC にローカルのまま置いてあり、Discord でメンションを一つ飛ばせばクロードがそれを読んで答える。**同期する必要がない — ファイルを動かすのではなく、ファイルがある場所へ質問を送る構造だからだ。**

ここに MCP を重ねるとさらに良くなる。Redmine のような社内システムを MCP でつないでおけば、ボットが予定や課題を取ってきて **Discord のチャットに見やすく整えて流してくれる。** ローカルのメモと MCP のデータを一箇所でまとめて要約してくれるので、別途ダッシュボードを作らなくても「今日は何がある」がチャット一行で終わる。

## ボットの機能

- メンション → スレッドを自動生成して返答
- 添付ファイルを自動ダウンロードし、クロードが Read ツールで分析
- スラッシュコマンド（`/予定登録`、`/予定一覧`、`/予定削除`）で予定通知（締切前日に 1 回 + 当日は毎時繰り返し、削除 = 完了扱い）

## セキュリティ設計

ボットがいるサーバーの **メンバー全員が自分の PC のクロードを使うことになる** ので、ツールを絞る必要がある。`--allowedTools` を読み取り／検索系（Read, Glob, Grep, WebSearch, WebFetch）と、許可する MCP ツール（`mcp__redmine__list_issues` など）だけに制限し、Bash・Write・Edit のような実行／書き込み系ツールは塞いだ。

## Discord ボットの登録手順

開発者ポータルで:

1. New Application → Bot メニューでトークンを発行
2. **MESSAGE CONTENT INTENT のスイッチを入れる** — 入れないとボットがメッセージを読めない。最も多いつまずきポイント。
3. OAuth2 URL Generator で `bot` スコープと必要な権限にチェック
4. 生成された URL でサーバーに招待

他のクロード契約者も自分のトークンと自分のサブスクで回せるように、zip（ボットのコード + `.env.example` + インストールガイド + `setup.bat`）にまとめてある。setup.bat が Python（winget）・discord.py のインストールと設定ファイルの生成まで自動化し、アカウントが必要な部分（Discord トークンの発行、クロードのログイン）だけが手作業として残る。

## 詰まった点と解決

- **ストア（MSIX）版の Python は AppData が仮想化される** ため、`%APPDATA%\Claude\claude-code\` の claude.exe を読めない（PowerShell からは見えるのに Python からは FileNotFoundError）。→ claude.exe を AppData の外のフォルダにコピーして解決。単独の実行ファイルなのでコピーだけで動く。
- **バッチファイルに日本語（韓国語）を入れると cmd がコマンドを壊す**（`chcp 65001` のあとパーサーがバイトオフセットを読み違え、`'laudeBot' は…` のような幽霊エラーが出る）。→ bat ファイルは ASCII のみにする。
- **PowerShell のパイプで多バイト文字を渡すとエンコーディングが壊れる。** → Python の subprocess から UTF-8 バイトを直接 stdin に書けば安全。Python の実行も `-u`（unbuffered）+ `PYTHONUTF8=1` が必須（付けないと print がバッファに閉じ込められてログが出ないか、絵文字の出力で落ちる）。
- **ボットを AI セッションのバックグラウンドプロセスとして起動すると、セッション終了と一緒にボットも死ぬ。** → bat をダブルクリックして独立したコンソールで実行する必要がある。コンソール窓を閉じるとボットは終了、最小化は問題ない。
- 同じボットトークンでプロセスを 2 つ起動するとゲートウェイに両方つながり、**返信が重複する。**

## メモ／考えたこと

- 結局、三度の「有料プランをどうぞ」を同じ手ひとつで乗り越えた。Slack のクロードタグ（チームプラン）、メモの同期（サブスク）、API 課金 — **自分の PC で動くボット一つ** で三つとも片付いた。
- 肝心なのはクロードをどこに置くかではなく、すでに自分の PC に整えてある環境（MCP・スキル・ローカルファイル）に **メッセンジャーという入口をひとつ開けたこと** だ。だから新しく設定するものがほとんどなかった。
- 次にやること: 起動時の自動スタート登録、スレッドごとのツール権限の分離。
