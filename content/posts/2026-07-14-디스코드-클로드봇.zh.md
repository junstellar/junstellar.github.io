## 一切从 Slack 开始

我想给团队项目管理搭一个「在聊天工具里用标签把 Claude 叫出来」的环境。Slack 本来就有官方接入 Claude 的功能（Claude in Slack，也就是所谓的 Claude Tag），我打算直接用——结果**它要求团队版**。对一个人用、或者小规模在跑的人来说，为了一个功能把整个套餐往上抬，怎么算都不划算。

于是我换了方向：「那就直接接到我自己在用的聊天工具上」，并把候选缩小。

- **KakaoTalk** —— 淘汰。普通聊天室根本没有可用的机器人 API。OpenBuilder 只面向 1:1 频道聊天机器人，非官方的自动化则有封号风险。
- **Telegram** —— 官方机器人 API 最简单，门槛也最低。但对话只有一条线，同时推进多个话题很快就会缠在一起。
- **Discord** —— 最终选它。

选 Discord 的理由很明确。

- **子区（thread）结构。** 一次提及就开一个子区，上下文自然按话题分开。这一点和后面的 `--resume` 会话映射严丝合缝。
- **频道分离。** 可以按用途分频道——工作、笔记、日程。
- **附件和代码块处理得当。** 传个文件上去，直接就能说「分析一下这个」。
- **机器人权限给得细。** 在哪个频道能做什么，都在服务器层面受控。
- **斜杠命令是一等公民。** 像 `/添加日程` 这种，可以连自动补全和参数校验一起做出来。
- 免费，而且有 PC 和移动端，出门在外照样能用。

## 核心架构

```
Discord @提及 → discord.py 机器人 → claude -p (headless Claude Code) → 发送回复
```

- `claude -p --output-format json` 会连同回复一起返回 `session_id`。把它和 Discord 的子区 ID 映射起来存好，下一条消息带上 `--resume <session_id>`，**每个子区就各自保有自己的对话上下文**。
- 只要 Claude Code 用订阅账号（Pro/Max）登录着，`claude -p` 就走订阅额度，**不需要 Anthropic 的 API 付费**。当初在 Slack 那边卡住的费用问题，在这里消失了。
- 即使在 headless 模式下，它也会**原样识别那台电脑上配置的全部 MCP 服务器和技能**。等于我在自己电脑上用的环境，原封不动搬到了 Discord 里。

## 意外收获：本地笔记同步顺手就解决了

我一直像用 Obsidian 那样，**把笔记以本地文件的形式攒着**。可想在手机上也能看，各家服务最后都会劝你上付费同步套餐。跟 Slack 那道墙一模一样。

结果接上这个机器人之后，这个问题整个没了。笔记文件仍然本地放在我电脑上，在 Discord 里提及一次，Claude 就把它们读出来回答。**根本不需要同步——因为这不是把文件搬过去，而是把问题送到文件所在的地方。**

再叠上 MCP 会更好。把 Redmine 这类内部系统用 MCP 挂上，机器人就能去查日程和工单，**在 Discord 聊天里整理得清清楚楚地铺出来**。它会把本地笔记和 MCP 数据放在一处汇总，所以不用另做仪表盘，「今天有啥」一句聊天就搞定。

## 机器人能做什么

- 提及 → 自动开子区并在里面回答
- 自动下载附件，再由 Claude 用 Read 工具分析
- 斜杠命令（`/添加日程`、`/日程列表`、`/删除日程`）做日程提醒（截止前一天提醒 1 次 + 当天每小时重复，删除 = 标记完成）

## 安全设计

因为**机器人所在服务器的每个成员都会用到我电脑上的 Claude**，工具必须锁死。我把 `--allowedTools` 限制在读取／检索这一类（Read、Glob、Grep、WebSearch、WebFetch），外加要放行的 MCP 工具（`mcp__redmine__list_issues` 等），并封掉了 Bash、Write、Edit 这些执行／写入类工具。

## Discord 机器人注册流程

在开发者门户里：

1. New Application → 在 Bot 菜单里签发 token
2. **打开 MESSAGE CONTENT INTENT 开关** —— 不打开机器人就读不到消息。这是最常见的坑。
3. 在 OAuth2 URL Generator 里勾选 `bot` scope 和需要的权限
4. 用生成的 URL 邀请进服务器

为了让其他 Claude 订阅者也能用自己的 token、自己的订阅跑起来，我把它打包成了 zip（机器人代码 + `.env.example` + 安装指南 + `setup.bat`）。setup.bat 会自动完成 Python（winget）和 discord.py 的安装以及配置文件生成，只把需要账号的部分（签发 Discord token、登录 Claude）留给手动。

## 卡住的地方和解法

- **从商店（MSIX）装的 Python，其 AppData 是虚拟化的**，读不到 `%APPDATA%\Claude\claude-code\` 下的 claude.exe（在 PowerShell 里看得见，在 Python 里却是 FileNotFoundError）。→ 把 claude.exe 复制到 AppData 之外的文件夹就解决了。它是独立可执行文件，复制过去就能跑。
- **批处理文件里放中文（韩文）会让 cmd 把命令弄坏**（`chcp 65001` 之后解析器读错字节偏移，冒出 `'laudeBot' 不是…` 这种幽灵报错）。→ bat 文件只用 ASCII。
- **用 PowerShell 管道传多字节字符会导致编码损坏。** → 从 Python 的 subprocess 直接把 UTF-8 字节写进 stdin 才稳。运行 Python 也必须加 `-u`（unbuffered）和 `PYTHONUTF8=1`（不加的话 print 会卡在缓冲区里导致看不到日志，或者在输出 emoji 时直接崩）。
- **把机器人当作 AI 会话的后台进程启动，会话一结束机器人也跟着死。** → 必须双击 bat，在独立的控制台里运行。关掉控制台窗口机器人就停，最小化则没问题。
- 用同一个机器人 token 起两个进程，两个都会连上网关，**回复就会重复**。

## 随想

- 说到底，我用同一招迈过了三次「请升级付费套餐」。Slack 的 Claude Tag（团队版）、笔记同步（订阅）、API 付费——**一个跑在自己电脑上的机器人**就把三件事全解决了。
- 关键不在于把 Claude 放到哪里，而在于**给我早已在自己电脑上搭好的环境（MCP、技能、本地文件）开了一道叫「聊天工具」的入口**。所以几乎没有什么需要重新配置的东西。
