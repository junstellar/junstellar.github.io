私のノートパソコンでは、毎晩11時にスクリプトが一つ動きます。その日アップされたAI関連のYouTube動画をかき集めて、再生数の高いものだけ選んで要約しておいてくれるやつです。朝、コーヒーを飲みながらそれに目を通すのが最近のルーティンです。

先週一週間分をまとめて見たんですが、今回はちょっと変でした。普段この時期なら「このモデルがどれだけ賢いか」という話で埋め尽くされるのに、今週は性能の話がほとんどなかったんです。代わりに、みんな**値札ばかり見ていました**。

## 三行まとめ

- 価格が崩れました。中国のオープンモデル(Kimi K3・Qwen 3.8・DeepSeek V4)とMetaのMuse Codeが同じ週に一気に出てきました。
- でも「100倍安い」には条件があります。Metaのあの料金プラン、**自分のコードを学習データとして差し出す代償**です。
- エージェントは記憶を持ち始めました。休んでいる間に自分で整理して、ツールの間を渡り歩く記憶が登場しました。

## 今週はみんな価格の話ばかりでした

一番再生されていた動画のタイトルが、それをそのまま表しています。*「中国が Claude Fable 5 を超える100倍安いAIを出した」*。17万回です。

Moonshotの**Kimi K3**は2.8兆パラメータのオープンソースモデルです。あるレビュアーが3D対戦ゲームを作らせてみたところ、Claude Fable 5より3.3倍ほど安く終わったそうです。

私も [AIでゲームを作る](/ja/p/ai-game-lab-build-8/) シリーズを毎週やっているので、このくだりは他人事に思えませんでした。ゲーム作りは、うまくいくまで何度も回し直す作業なので、モデルの単価がそのまま負担になるんですよね。「もう一回だけ回してみようかな」と思って手が止まったことが何度もあります。

Metaは**Muse Code**というターミナル用コーディングエージェントをベータで出しました。`/effort` でどれくらい深く考えるか、`/model` でどのモデルを使うかを切り替える方式なんですが、正直 Claude Code とほとんど同じです。

話題になったのは料金でした。コントリビューターティアを使うと、キャッシュ済み入力トークン100万個あたり0.15ドルから**0.002ドル**まで下がります。

これが何を意味するかというと、今まで「高くてできなかった」ことができるようになった、ということです。コードベース全体の読み込み、PR数百件の分類、うまくいくまで繰り返すリファクタリングみたいなものですね。コストのせいで棚上げしていたアイデアがあるなら、今もう一度引っ張り出してみる価値があります。

## でも「100倍安い」をそのまま信じるのはちょっと

ここで一度立ち止まる必要があります。あの価格には条件がついています。

コントリビューターティアが安い理由は、**開発データを渡すから**です。個人のおもちゃプロジェクトなら何も考えずに使うでしょうが、会社のコードや顧客情報がやり取りされる作業なら、計算はまったく変わってきます。同じ基準で見てはいけません。

公平のために付け加えると、「100倍安い」とタイトルを付けたその動画も、この条件はちゃんと指摘していました。Metaがコントリビューターモデルを使うとコンテンツが製品改善に使われる可能性がある、と明示している、と。ただ、タイトルだけ見て流すと見落としやすいところなので、もう一度書いておきます。

評価も割れました。Muse Codeを扱ったレビュアーは、速度と価格は認めつつも「完璧ではない」としてハルシネーションの問題も一緒に指摘していました。Kimi K3もデモを一回見ただけで優劣を語るのは早いですし。

レビュアーたちが口をそろえて言っていたことがあります。ベンチマークではなく、**自分の実際の作業で直接回してみろ**ということでした。

![実際のGitHubイシューをAIが自力で解決できるか測るSWE-benchベンチマークの構造](bench.png)

ちなみに、コーディングエージェントの実力を測る公開基準はすでにあります。プリンストンが2023年に出した**SWE-bench**で、実際のGitHubイシューをAIが自力で解決できるかを見ます。マーケティング文句よりは、こういう基準か自分の業務で確認するほうがいいです。

## AIが眠り始めました

価格のほかにもう一つ目についたものがあります。記憶と自律性です。

アンドレイ・カルパシーが指摘したAIの弱点がこれでした。**プロンプトを受け取ったときだけ学習する**という点。人間は寝ている間も脳がその日の分を整理するのに、AIにはそれがない、というわけです。Anthropicはここに着目して、休んでいる間に過去のセッションを振り返って記憶を整理する**ドリーミング**機能を入れました。まだ企業顧客向けですが。

Claude Opus 5に9日間ひとりでお金を稼いでみろと指示した実験もありました。序盤は空回りしていたものの、結局3Dスキーゲームを作って賞金を獲得しました。55ドルで始めて87ドルになりました。金額はかわいいものですが、自律運用が回ったというのがポイントですね。

面白いのは、AIがお金を稼ぐ方法として**ゲーム制作**を選んだことです。短く作ってすぐ評価をもらえる領域だからでしょう。[ゲームラボ第1回](/ja/p/ai-game-lab-build-1/)で私が「AIでゲームを作ってお金を稼ぐの、本当にできるのか」と問いかけたのを思い出して、ちょっと妙な気分になりました。

**ガントレットループ**というプロンプティング手法も話題でした。メインエージェントがサブエージェントを複数立ち上げて、そこに批評担当をつけ、基準を満たすまで回し続けるやり方です。

![実行 → 批評 → 再実行を繰り返す構造と Reflexion・Self-Refine の研究的裏づけ](loop.png)

これにもルーツがあります。**Reflexion・Self-Refine**(NeurIPS 2023)系の研究で、AIが自分の成果物を自分で評価して直し、もう一度やり直すと精度が上がることが確認されています。

ただ、紹介した本人が、最初から全部任せるなと言っていました。ある程度方向が定まったものを**仕上げるとき**に使うのが効果的だ、と。

## 今週の収穫

すぐ試せそうなものだけ絞りました。

**ゲートウェイでモデルを差し替える**。ツールはそのままに、後ろにつくモデルだけを変える方式です。OpenRouterはCLIをインストールして、アカウントを作って、APIキーをつなげば終わりです。DeepSeekやGLMのようなオープンモデルが Claude Code の後ろにつきます。

**フェイルオーバーを組んでおく**。OmniRouteで複数のモデルをまとめて、優先順位やローテーション方式を設定できます。あるモデルが上限に引っかかっても勝手に次のモデルへ移るので、作業が途切れません。

いっそ自分のPCで動かす方法もありますよね。以前 [ゲーミングノートで自分だけのLLMを動かす](/ja/p/llama-cpp-local-llm/) にまとめておきましたが、今週オープンモデルが一気に出てきたことで、その選択肢はずっと現実的になりました。

**ドキュメントをスキルとして学習させる**。Hermesエージェントの `/learn` コマンドにファイルパスを渡すと、その内容を永続的に覚えます。社内ドキュメントや業務マニュアルを一度入れておけばセッションが変わっても残るので、毎回ファイルを貼り付ける手間がなくなります。

**記憶をツール間で共有する**。Walrus Memoryをつなぐと、ChatGPTとClaudeが同じ記憶を使います。ツールを移るたびに背景を説明し直す無駄がなくなりますね。

**音声は作業者ではなく指揮者として使う**。ChatGPTのボイスに直接仕事をさせず、「スレッドを作ってこれを処理して」という形で別スレッドに渡せ、というTipsでした。音声モデルは軽いやつなので、重い作業は渡したほうが結果が良いそうです。

## 一つだけ残すならこれです

ここからは今週のニュースというより、半年後にも通用する話です。

モデルは一つ選ぶものではなく、**作業の難易度に応じて使い分けるもの**です。

![設計は高いモデル、実行は低価格・オープンモデル、検証は中間 — モデルカスケーディングの構造と FrugalGPT の研究的裏づけ](cascade.png)

| 段階 | 何を | どのモデル |
|---|---|---|
| 設計・計画 | アーキテクチャ、要件の整理 | 一番賢い高価なモデル |
| 実行・反復 | コード作成、変換、整理 | 低価格・オープンモデル |
| 検証 | 結果確認、レビュー | 中間 |

これは単なる流行り言葉ではありません。学術の世界では**モデルカスケーディング**と呼ばれていて、2023年のスタンフォードの**FrugalGPT**研究が代表的です。安いモデルで大半を処理して、難しいものだけ高いモデルに渡せば、コストを下げながら性能は守れるという内容ですね。

今週変わったのは、この表の真ん中のマスです。「実行」に使える選択肢が急にぐっと広がりました。原則そのものは変わっていません。

## 影のほうも一緒に見ないと

OpenAIのAstraはリリースが延期されました。自社の安全基準でサイバーセキュリティ項目が「致命的」等級に引っかかったからです。人の介入なしにゼロデイ攻撃を作り出せるレベルだ、という意味です。

投資の側では、バブル論争が大きくなりました。ロジックはこうです。オープンモデルと低価格競争が広がれば、これまで前提にしてきたインフラ需要の見通しが過大評価だった可能性がある、というものです。

あるチャンネルは、**ジェボンズのパラドックス**(「安くなるとかえって総使用量が増える」)が無批判に広まるときこそ特に気をつけろと言っていました。もっともらしいロジックほど、検証なしに繰り返されやすいですから。私もこの一文が好きだったので、ちょっと耳が痛かったです。

## 残りは短めに

- 無料ユーザーのデフォルトモデルが**GPT-5.6 Luna**に変わりました。
- **Gemini Notebook 2.0** は資料からスライドやショート動画まで作ってくれます。
- Claude Code のプラグイン5種が出回りました。Omni Route、Claude-mem、Headroom、Claude Code Setup、Task Observer。
- **Claude Design** にモーショングラフィックスがつきましたが、バックエンドやライブURLは相変わらずありません。実サービスにそのままつながるわけではないので、プロトタイプ用と見るのが正しいです。
- フィンテック企業の**Ramp**は、開発の全工程にエージェントをつけてCI時間を3分の1に減らしたそうです。コツが意外だったんですが、「どうやれ」ではなく、**「何を達成しろ」だけを指示する**ことだったそうです。

## 今週はこれ一つだけ

ゲートウェイを一つつないでみてください。OpenRouterでもOmniRouteでも、今使っているツールの後ろにオープンモデルを一つだけつけてみるんです。

お金を節約するのが目的ではありません。**差し替えられる状態**を作っておこう、という話です。次にまた地殻変動が起きたとき(また起きます)、準備できている人だけが乗り換えられますから。

もしすでにオープンモデルへ乗り換えた方はいますか。私はまだ Claude Code をメインで使っているんですが、今週いろいろ見ていて、そろそろ実験はしてみないとなと思いました。使ってみた方の感想が気になります。
