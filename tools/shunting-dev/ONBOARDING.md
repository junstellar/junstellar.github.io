# 조차장 — 온보딩 설계 (확정안)

> **사용자 피드백 원문:** "게임 방법을 모르겠는데" → "클리어 방법이 뭔데" → "기관차를 어떻게 빼는데"
> → "미션이 뭐였는데" → **"어떻게 게임하는건지 알아차리는데 한참걸렸다"**
>
> 룰은 단순한데 게임이 그걸 **한 번도 말해주지 않는다.** 시각 품질 심사 39명이 이 문제를
> 한 번도 지적하지 않았다 — 아무도 "처음 보는 사람이 플레이할 수 있는가"를 묻지 않았기 때문이다.
>
> **이번 작업의 유일한 성공 기준: 설명 없이 처음 보는 사람이 LV01~03을 클리어한다.**
> 예쁘게 만드는 게 아니라 **알아먹게** 만드는 일이다.

## 이미 고쳐진 것 (다시 하지 마라)
- ✅ **줌** — `Render.zoom` 계수 0.0012 → `ln(1.10)`. 휠 1노치 = 거리 10%. 핀치는 비율 기반 1:1 추적.
- ✅ **숫자키 매핑 고정** — 항상 `1=S1 2=S2 3=S3 4=EXIT 5=HEAD`, 없는 선로는 빈 슬롯(null).

## 남은 결함

| # | 결함 | 증거 |
|---|---|---|
| 1 | 규칙 설명이 화면 어디에도 없음 | UI 전체 텍스트 = `LV 01 \| 아침 첫 입환 \| 0 / par 3 \| 편성 목표 \| 0/2 \| 서 동` |
| 2 | 선로 이름표가 화면에 없음 | 내부는 "측선 1"·"출발선"을 알고 토스트에도 쓰는데 화면 표시 0 |
| 3 | 분리(cut)가 3D 연결기 클릭 전용, 타겟 ~10px | 프록시 반지름 1 월드유닛. 모바일 터치 불가. 키보드 대체 없음 |
| 4 | "기관차가 출발선에서 나와야 승리" 규칙이 비공개 | 화차를 다 놓고도 안 끝나 막힘 |

## 설계

### A. 첫 실행 튜토리얼 (LV01~03, 단계 게이트) — **사용자가 직접 요청한 것**
한 번에 **한 가지만** 가르치고, 그 동작을 해야 다음으로 넘어간다.

**LV 01 — 조작**
1. "측선 1을 탭하세요. 기관차가 가서 화차를 **자동으로 물어옵니다**."
2. "출발선을 탭해 화차를 밀어 넣으세요."
3. "✂ 를 눌러 기관차를 **분리**하세요."
4. "인상선을 탭해 기관차를 빼면 **완료**입니다."

**LV 02 — 후입선출(핵심 개념)**
- "측선은 **막다른 길**입니다. 먼저 넣은 화차가 **안쪽**에 갇혀요.
  순서를 바꾸려면 다른 측선에 **잠시 내려놓아야** 합니다." + 인라인 SVG 도해(넣는 방향/나오는 방향)

**LV 03 — 부분 분리**
- "✂ 로 **일부만** 떼어놓을 수 있습니다. 분리는 **수를 소모하지 않습니다.**"

규칙:
- 해당 동작을 하면 **자동으로** 다음 단계. 틀린 곳을 탭하면 막지 말고 부드럽게 다시 안내.
- **건너뛰기 버튼 필수** (사용자 요청). 누르면 그 레벨 튜토리얼 전체를 종료.
- 본 단계는 localStorage 저장 → 다시 안 뜸. 단 **`?fresh=1` 이면 무시하고 처음부터** (검증에 필요).
- 말풍선은 **한 문장**. 화살표로 어디를 누를지 명확히.

### B. 편성 바 — 분리의 주 경로 (3D 연결기 사냥을 대체)
화면 하단에 **지금 물고 있는 편성**을 칩으로 표시.
```
  ┌────┐ ✂ ┌────┐ ✂ ┌────┐
  │ 🚂 │   │유개│   │유조│
  └────┘   └────┘   └────┘
           k=0      k=1
```
- `✂` 는 **최소 44×44 CSS px** 터치 타겟. 탭 → `hooks.onCut(k)`.
  기관차 바로 뒤 = `k=0`(전부 내려놓기). **마지막 화차 뒤에는 ✂ 를 두지 않는다.**
- 칩은 목표 스트립과 **같은 타입 SVG 실루엣**을 재사용 (같은 그림이어야 학습이 된다).
- 편성이 비면 바 전체를 숨긴다.

### C. 선로 이름표
각 선로 서쪽 끝 위에 DOM 라벨. 월드좌표 → 매 프레임 화면좌표 투영.
```
 ┌──────────────┐
 │ ④ 출발선  0/6 │   활성: 밝게 + 액센트 테두리
 │ ① 측선 1  2/4 │   불가: 흐리게 + 사유
 └──────────────┘
```
- **라벨 자체가 탭 가능**해야 한다 (3D 조준 실패를 구제하는 안전망).
- 상태 3가지: `active` / `here`(기관차 위치) / `blocked`(+사유).
- **DOM 재생성 금지** — 최초 1회 만들고 이후 `transform`/`textContent` 만 갱신.

### D. 3D 연결기 개선 (보조 수단)
- 프록시 반지름을 카메라 거리 기준 동적 스케일 → **화면상 최소 24 CSS px**.
- **보이게** 만들어라: 은은한 링/글로우 마커, 호버 시 강조.
- 키보드: `Q` = `cut(0)`, `W` = `cut(1)`.

### E. 승리 조건 안내
`tracks.EXIT` 가 목표와 일치하고 `consist` 가 비었는데 아직 승리가 아닐 때:
- 인상선 라벨 **펄스** + 토스트 **"편성 완료! 기관차를 출발선 밖으로 빼면 끝납니다."**
- `50-puzzle.js` 를 고치지 말고 Game 에서 조건 검사로.

### F. 규칙 카드 (`?` 버튼)
언제든 볼 수 있는 3장 요약: **목표** / **조작** / **제약(후입선출·인상선 용량)**.
튜토리얼을 건너뛴 사람의 안전망이다.

### G. 줌 버튼 (선택)
휠이 없는 터치 기기를 위해 `+` / `−` 버튼을 버튼 클러스터에 추가하면 좋다.
`SH.Render.zoom(-1)` / `zoom(+1)` 을 호출하면 된다 (1 = 10%).

## 파일별 담당 & 인터페이스 계약
**공개 API 는 추가만. 기존 시그니처를 깨지 마라.**

### `js/80-ui.js` (SH.UI) — 이번 작업의 핵심
```
UI.consist(list, hooks)   // [{id,type,livery}] 기관차 제외, 서→동. 빈 배열이면 숨김. ✂ → hooks.onCut(k)
UI.labels(list)           // [{id,name,key,x,y,visible,state,reason,count,cap}] x,y=CSS px. 매프레임 호출됨
UI.tutorial(step)         // {level,index,total,text,anchor:'track:S1'|'consist-cut'|null,arrow:bool}
                          // null 이면 닫기. '건너뛰기' → hooks.onTutorialSkip()
UI.rules(open)            // 규칙 카드
UI.hintPulse(target)      // 'track:HEAD' 강조 펄스
```
기존 UI(상단 바·목표 스트립·승리 오버레이·레벨 선택)는 이미 좋다. **망가뜨리지 마라.**

### `js/70-input.js` (SH.Input)
- 연결기 프록시 동적 스케일(화면 ≥24px) + 가시화
- `Q`/`W` → `hooks.onCoupler(0)` / `(1)`
- `SH.Input.trackAnchor(trackId)` → 라벨 붙일 월드 좌표(서쪽 끝, 지면 위 약 6유닛)
- ※ `trackKeys` 고정은 **이미 완료됨** — 건드리지 마라.

### `js/90-game.js` (SH.Game)
- 매 프레임 라벨 데이터 공급: `Input.trackAnchor` → `Render.screenPos` → `{x,y,visible}`,
  `Puzzle.legalGo` → `state`/`reason`. 사유 한국어:
  `same`="기관차가 이미 여기 있습니다" / `head-full`="인상선에 다 들어가지 않습니다" /
  `track-full`="이 선로가 가득 찼습니다"
- 상태 변경 시 `UI.consist()` 갱신, `hooks.onCut(k)` → `Puzzle.cut` → Motion 분리 연출
- 튜토리얼 상태 머신 + 건너뛰기 + localStorage
- 승리 직전 안내(E), `?` 버튼 → `UI.rules(true)`
- **`?fresh=1`** — 진행도·튜토리얼 기록 무시하고 완전 초기 상태 (검증에 필수)
